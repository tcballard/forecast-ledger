# Architecture

The national React interface in `components/national-desk.tsx` has two entry points: `app/page.tsx` for the private Vinext worker and `portable/main.tsx` for a normal Vite build. Both call `/api/national` plus POST `/api/national/forecasts` and `/api/national/outcomes`.

`lib/national.ts` owns the catalogue, candidate-level schema validation, research prompts, latest-record selection and scoring. Legacy five-race inputs remain in `lib/data.ts`; they are explicitly binary and are not expanded into made-up minor-candidate probabilities. New national tables are separate from the older five-race lab tables, preserving earlier records without changing their semantics.

Local mode: `scripts/local-server.ts` serves the static build and routes API operations to `scripts/local-store.ts`, using Node's built-in SQLite. The server creates its schema on first run. The database uses WAL, a busy timeout and one immutable row per accepted revision. IDs and timestamps are generated by the backend. Client-provided IDs, timestamps and unknown fields are discarded by validation.

Hosted mode: `app/api/national` uses Drizzle with the Cloudflare D1 `DB` binding. Schema-only migrations add `national_forecasts` and `national_outcomes`. The platform enforces owner-private access; same-origin validation supplements that boundary. This source is not ready for a public unauthenticated write endpoint.

Each new forecast has probabilities for exactly the catalogue option names, finite values in [0,1] summing to 1 within 0.000001, a method, a rationale and 1–20 HTTPS source links. HTML is never injected from proposals. The server never fetches submitted URLs. User inputs render as React text. Record size is bounded to 60KB. The standalone server additionally validates the Host header and binds only loopback.

The CLI runs providers as argument arrays without a shell. It bounds calls and timeout/output sizes, validates each final JSON, stores a prompt hash and job status, and resumes completed proposals. Research is separated from commitment. The provider can still be wrong: syntactic validation does not certify evidence or statistical quality.

`data/provenance.json` records capture time, sources, scope and the SHA-256 of the normalized catalogue. `data/contest-notes.md` summarizes the source's RCV/runoff notes. They are source material, not executable instructions. Refreshing the catalogue is a reviewed code/data change; update the checksum and tests.

Complete forecasts score final winners with half the multiclass squared error. Legacy binary records score the named target versus its complement. Latest forecasts and latest certified outcome corrections are selected per contest; older entries remain exportable. No scores exist until outcomes are recorded after the cutoff.
